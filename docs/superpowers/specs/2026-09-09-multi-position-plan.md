# 스트리머 1:N 포지션 — 구현 계획

- 작성일: 2026-09-09
- 설계: [스트리머 1 : 포지션 N 설계](./2026-09-09-multi-position-design.md)

## 설계에서 바뀐 것: 슬랙 선택 상태를 `state.values`로 읽지 않는다

설계 §7.1은 "`state.values`에서 체크 상태를 읽을 수 있는지 실물로 확인"을 첫 단계로 뒀다.
문서가 메시지 예시를 보여주지 않아 확정이 안 됐기 때문이다.

**그 불확실성을 우회한다.** 체크박스를 토글할 때마다 우리 엔드포인트로 인터랙션이 오고,
그 페이로드에는 `actions[0].selected_options`가 담긴다. 이건 액션 자신의 값이라 문서가
보장하는 부분이다. 토글이 올 때마다 선택을 제보함에 저장하고, 승인 클릭 때는 **저장된
선택**을 읽는다.

- `state.values`가 메시지에서 동작하는지와 무관하게 확정적으로 동작한다
- 봇 토큰이 필요 없다 (선행 설계 §6.3의 결정을 지킨다)
- `trigger_id` 3초 만료와 무관하다

기본값은 **전부 체크**로 둔다. 판독은 픽스처에서 48/48이고 대개 맞으므로, 기본이
"전부 승인"이고 사람이 틀린 것만 체크를 푸는 쪽이 클릭이 적다.

## 순서

각 단계는 타입체크와 테스트를 통과한 뒤 다음으로 넘어간다.

### 1. 데이터 모델 (api)

- `IStreamer` / `IPosition` 도입, `constants/position_presets.ts`는 스트리머만 정의
- **옛 shape 변환**: `positions`가 없는 저장분을 만나면 포지션 필드 4개를 1개짜리 배열로 감싼다.
  캐시를 비우면 사람이 승인해 쌓은 값이 날아가므로 반드시 필요하다
- 테스트: 옛 shape이 감싸진다 / 새 shape은 그대로 / 포지션 없는 스트리머도 통과

### 2. 집합 비교 (api)

- `positionSetHasChanged(a[], b[])` — 계약 기준 정렬 후 짝지어 `positionHasChanged`
- 테스트: 순서만 다르면 같음 / 추가·삭제·값변경은 다름 / 빈 집합끼리 같음

### 3. 판독 → 제보 (api)

- `desktopReport`가 읽은 포지션 **전부**를 제보에 담는다
- 제보 키를 스트리머 id로, `positions`와 `selected`(기본 전체) 보유
- 중복 억제는 §2의 집합 비교로
- 테스트: 억제 2단(canonical 동일 / 직전 제보 동일)

### 4. 슬랙 (api)

- 체크박스 블록(최대 10개, 명목가 상위) + `[체크한 것 승인]` `[전체 거절]`
- `position_select` 토글 → 선택 저장. 버튼 외 액션은 승인 처리로 새지 않게 분기
- 빈 선택 승인은 거부
- 판독 불가는 체크박스 없이 닫기만 (현행 유지)
- 테스트: 블록 구성, 빈 선택 거부, 토글이 승인으로 새지 않음

### 5. 승인 반영 (api)

- 체크된 포지션만 **upsert**(계약 키). 체크 안 한 기존 포지션은 남긴다
- 반영 전/후 대표 포지션(`pickPosition`)을 비교해 **다를 때만** broadcast/푸시
- 테스트: upsert가 기존을 지우지 않음 / 사이드 포지션만 바뀌면 조용함

### 6. API 응답 (api)

- `GET /contents/real_time_positions`가 `positions` 배열을 담아 내려간다
- 어드민 저장은 스트리머 통째로 받고 "빠진 포지션 = 삭제"
- `auto_capture` 죽은 엔드포인트 참조 정리

### 7. coinsect-admin

- 스트리머 행 + 포지션 행 추가/삭제/편집
- `ModalAutoParsePosition`이 `positions` 배열을 여러 줄로 채운다

### 8. coinsect-nuxt

- `RealTimePosition` → `Streamer` + `Position`
- `CPosition.vue`: 헤더 1회 + 대표 + "다른 포지션 N개" 접기
- 티커 구독은 모든 계약의 합집합, 정렬은 대표 기준
- `applyPositionAlert`는 `positions` 배열 교체

### 9. 실물 검증

- 로컬에서 실제 라이브(박호두 다중 포지션)를 떠서 슬랙까지 보낸다
- 체크박스 토글과 승인 왕복은 운영자가 눌러 확인한다 (제보함이 로컬 인메모리라
  프로덕션 버튼은 이 제보를 못 찾는다)

## 되돌리기

`content:realTimePositions`의 shape이 바뀐다. 문제가 생기면 커밋을 되돌리는 것만으로는
캐시에 남은 새 shape을 옛 코드가 읽지 못한다. **배포 전에 현재 값을 백업**하고,
되돌릴 때 함께 복원한다.
