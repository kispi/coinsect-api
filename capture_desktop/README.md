# capture_desktop

가정용 IP에서 유튜브 라이브 프레임을 떠서 서버로 보내는 클라이언트.

운영 서버(EC2)의 IP는 유튜브가 봇으로 차단해 `yt-dlp`가 라이브 주소를 해석하지 못한다.
그래서 이 부분만 집에서 돌린다. 여기서 하는 일은 캡처와 전송뿐이고,
포지션 인식(Gemini)과 판정은 전부 서버에 있다.

집은 NAT 뒤에 있으므로 서버가 집을 부르지 않는다. **집이 주기적으로 서버를 부른다.**

## 준비물

- Node.js 22 이상 (`--env-file`과 전역 `fetch`를 쓴다)
- `yt-dlp`, `ffmpeg` — PATH에 있거나 `.env`에 경로 지정

의존성 설치는 필요 없다. `node_modules`가 없다.

## 실행

처음 한 번만:

```bash
cp .env.sample .env   # DESKTOP_SECRET을 서버 .env와 같은 값으로 채운다
```

### 켜두는 용도 (출근용)

```bash
npm start
```

인자가 없으면 등록된 대상 전부를 시간대별 주기로 계속 돈다.
21~3시(KST)는 5분, 나머지는 1시간. 창을 닫으면 멈춘다.

켜두고 출근하면 된다. 꺼져 있으면 제보가 안 올 뿐 서버는 멀쩡하고,
어드민의 수동 업로드 경로도 그대로 살아 있다.

### 한 명만 지금 긁기 (손으로 확인할 때)

이름의 일부를 넘기면 **그 한 명만 긁고 끝난다.** 루프가 도는 것을 기다릴 필요가 없다.

```bash
npm start -- 짭구
# 또는
node --env-file=.env index.js 짭구
```

- 이름 일부만 넘겨도 잡힌다(`includes`). 여럿 걸리면 **첫째만** 쓰고 누가 걸렸는지 찍는다
- 맞는 대상이 없으면 등록된 이름을 전부 보여주고 **종료 코드 1**로 끝난다
- 캡처가 실패하면 종료 코드 1. 성공하면 0이라 다른 스크립트에서 이어 쓸 수 있다

여기서 말하는 '등록된 대상'은 `constants/position_presets.ts`가 아니라 **서버에 등록된
스트리머 중 `channelUrl`이 있는 것**이다. 프리셋에 있어도 어드민 '포지션 생성'으로
등록하지 않았으면 대상이 아니다.

`yt-dlp`는 유튜브 변경에 맞춰 자주 갱신해야 하므로 가끔 `yt-dlp -U` 해준다.
